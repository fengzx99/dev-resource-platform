1. 版本与交付范围

发布版本 2026.10.21，应用基线 1.1.0。这是当前线上代码的离线快照；健康接口仍返回应用基线 1.1.0。具体镜像 ID、源文件 SHA-256 和依赖清单以 manifest.json 为准。

包含固定三类挂载、root 开发容器登录、全局共享读写、实时 GPU/进程监控、资源分配历史和统计导出、开发者账户设置、管理员重置密码及镜像目录移除。未集成 Slurm 或 Ray 作业调度。

现网主项目：/mnt/juicefs/software/dev-resource-platform；门户：https://172.16.9.20:8420/。本次发布只制作交付物，不需要重启当前服务。

父目录挂载思路与 /root/run_docker.sh 一致。执行器会校验实际来源：NFS 必须是该节点 IP 的 :/data-local；本地 bind 的挂载根应是 /data-local。当前 .20 的 /mnt/server003 是本机 /data-local 的 bind。不要把未挂载的本地空目录当成数据盘。

# 仅在新机器上、确认 /data-local 已指向正确数据盘后，由运维准备挂载：
mkdir -p /mnt/server003
mount --bind /data-local /mnt/server003
findmnt /mnt/server003
# 共享盘必须先正确挂载 JuiceFS，再准备共享目录：
mkdir -p /mnt/juicefs/share
# 按现有共享数据权限策略赋予容器 root 读写权限，不递归重写历史文件权限。

新增其他 IP 时需审核 app/storage.py 的 IP_ROOTS、准备实际挂载并重新构建平台镜像和发布包；仅修改 manifest 不会让执行器接受新 IP。/data 与 /root 在各自节点的数据盘上，不会自动跨节点迁移。/share 依赖共同挂载的 JuiceFS。固定目录不再要求手工创建旧式存储卷。JuiceFS 元数据连接只用于旧式卷配额管理；安装日志显示其 MISSING 时，不影响三类固定目录使用，但旧式配额功能需运维另配元数据连接。

5. 全新离线安装

单文件部署包先校验，再解包：

cd /mnt/juicefs/software
sha256sum -c dev-resource-platform-2026.10.21-linux-amd64.tar.sha256
tar -xf dev-resource-platform-2026.10.21-linux-amd64.tar

以下命令在新的控制节点或尚未安装该平台的主机执行。示例 IP 需替换为本机映射表中的地址。现网已有平台不要直接执行 --install。

cd /mnt/juicefs/software/dev-resource-platform-release-2026.10.21
sha256sum -c SHA256SUMS
python3 verify.py

# 只检查；目标目录必须尚不存在，且父目录位于 JuiceFS
python3 deploy.py --host 172.16.9.20 \
  --target /mnt/juicefs/software/dev-resource-platform

# 检查通过后，执行全新安装
python3 deploy.py --host 172.16.9.20 \
  --target /mnt/juicefs/software/dev-resource-platform --install

安装器依次校验全部交付文件，检查主机与挂载，导入六个离线镜像，将源码及 wheel 解压到目标目录，预置开发镜像共享缓存，生成独立密码和证书，启动数据库、认证、执行器及门户，最后使用正式 API 初始化项目与镜像目录。安装不依赖公网拉取。

默认创建：

  • admin（平台管理员）、developer（开发者），密码均随机生成；不沿用现网口令。
  • “开发资源项目”，默认项目与 developer 成员配额均为 8 CPU、32GiB 内存、1 GPU、1000GiB 旧式卷配额和 3 个环境；按实际业务在界面调整。
  • 2C4G 无 GPU 与 8C32G1GPU 两种套餐；一个 root 登录 / 三类持久存储开发镜像。
  • 全平台 global-share 条目；没有自动创建开发容器，不占用训练卡。
cd /mnt/juicefs/software/dev-resource-platform
# 仅在受控终端读取首次凭据，不粘贴到共享报告或部署包：
cat runtime/secrets/initial-access.txt
# 门户地址：https://172.16.9.20:8420/
# 安装报告预期含：PREFLIGHT PASS / DEPLOYED / initialization PASS / INSTALL PASS

initial-access.txt 只记录初始化时的口令，不会随用户以后改密而自动更新。Keycloak 导入文件与 platform.json 中的初始密码也不代表用户后来的实际密码。日常密码重置使用平台用户管理；用户自己改密使用账户设置。

仅做无 GPU 安装演练可额外传入 --no-gpus --prefix drp-test --port 18420，并使用另一个不存在的目标目录。这种实例不能验证 GPU 设备分配。不要把两个正式控制平面共同管理同一批开发容器。

6. 安装验收

docker ps --filter name=drp-
curl --cacert /mnt/juicefs/software/dev-resource-platform/runtime/secrets/server.crt \
  https://172.16.9.20:8420/healthz
# 预期：status=ok，version=1.1.0；发行版号在 RELEASE.json/manifest.json 中查看。
cat /mnt/juicefs/software/dev-resource-platform/RELEASE.json
  1. 分别用 admin/developer 登录；账户设置可打开密码修改和个人资料页面。管理员用户管理应可重置 developer 密码；重置后用户需重新登录。
  2. 管理员节点资源：在线、共享存储/固定存储检查通过；镜像目录仅有一个当前 root 镜像且状态“可用”。按实际机器调整项目、成员配额与套餐。GPU 全被其他容器访问时，独占申请可能排队。
  3. developer 申请 1 小时的轻量开发环境，填写自己的 SSH 公钥。检查容器详情 SSH 命令使用 root；/data、/root、/share 固定挂载均为读写。
  4. 在页面终端或用户自己的 SSH 会话中执行以下命令。开发者 SSH 用个人私钥，与网页登录密码无关。
whoami
printf '%s\n' "$HOME"
for d in /data /root /share; do
  f="$d/.drp-write-test-$(date +%s)-$$"
  printf 'ok\n' > "$f" && cat "$f" && rm "$f"
done
# 预期 root、/root，三个目录都输出 ok。
# 然后停止并启动这个验收环境，验证自行创建的持久测试文件仍存在。
  1. 申请有授权 GPU 的环境并运行自己的 GPU 测试，打开资源监控：管理员可查看节点全量 GPU/进程；开发者可查看自己当前运行环境实际分配卡上的所有进程，包含共享该卡的其他用户任务。没有分配卡时不显示其他卡的进程。
  2. 资源监控检查 CPU、内存、存储和 GPU 利用率。按用户/项目查看资源历史和统计并导出 CSV，等待至少一个采样周期。分配历史是容器分配记录，不能将共享卡总体利用率当作某个用户独占使用量。
  3. 停止/删除验收环境并确认它的测试任务退出；固定数据目录保留。只清理自己创建的验收文件。

采样约每 60 秒一次；指标保留 30 天；单次查询时间范围最长 31 天；分配历史长期保留。共享 GPU 不保证空闲显存/算力，不会自动中断外部训练任务。

7. 常用运维与生命周期

操作行为 / 注意事项
查看日志docker logs --tail 100 drp-portal / drp-executor / drp-keycloak / drp-database；日志可能含进程命令和业务路径，分享前检查
重启门户docker restart drp-portal；会短暂影响网页/API，不主动销毁现有开发容器
重启执行器docker restart drp-executor；短暂暂停资源操作，现有 Docker 开发容器继续运行；先确认挂载没有变化
停止或到期平台会移除开发容器并终止容器内进程；/root、/data 和 /share 文件保留；再次启动重建运行实例
删除开发环境结束该环境；固定数据目录保留，需要运维按归档策略另行处理
续期到期时间按“当前时间＋申请小时数”重设；操作前确认新的到期时间
重置用户密码仅管理员操作；使目标用户网页登录会话失效，不停止其训练容器
停用用户或修改角色可能触发该用户环境停止；维护前先核对运行任务
移除镜像管理员目录软移除；底层 Docker 镜像、数据和历史记录保留；仍被环境引用时会拒绝移除
节点维护停止接收新申请，不等同于自动迁移现有任务；当前节点是否接单以节点页开关为准

不要用 docker system prune --volumes 或批量删除 drp-ws-* 代替平台资源管理；数据库卷、历史固定目录和外部训练容器不属于发布包清理对象。证书到期前更新 runtime/secrets/server.crt 与 server.key（私钥权限 600），再重启门户；改域名/IP需同时审核 OIDC issuer、redirect URI、节点地址与存储映射，不只改浏览器 URL。

8. 账号、密钥、数据库与文件备份

cd /mnt/juicefs/software/dev-resource-platform
python3 scripts/backup.py --verify-restore
# 生成 runtime/backups/<UTC时间>/platform.dump、secrets.tar.gz、manifest.json
# verify-restore 在临时数据库恢复并比较关键表行数，结束后删除临时数据库。

这个备份同时覆盖 public 平台表和 keycloak 账号/凭据表，secrets.tar.gz 保存平台服务密钥、TLS 和节点连接配置。仅备份用户列表或 platform.json 不能恢复实际登录密码。运行大量统计采集时，临时恢复校验以关键业务表为主；正式备份需另行复制到受控备份位置。

还需单独备份：项目 data/.cluster-id（存储身份）、data/volumes 中保留的旧卷、各节点父目录下 user_data/user_home、/mnt/juicefs/share，以及扩展节点本机 /var/lib/dev-resources/nodes 中的证书和令牌。推荐用文件系统快照/备份软件；运行中的模型文件可能仍在写入，需安排一致性窗口。发布包未包含这些文件。

将备份目录设为仅 root 可读，保留不同时间点。不要把 secrets.tar.gz、数据库 dump 或容器 inspect 全量输出放入公开部署包。数据库命名卷属于运行数据，即使旧发布包删除也必须保留。

9. 当前站点更新与回滚

当前站点已经运行本次功能，发布离线包本身无需再部署。已有站点使用备份＋定向更新流程；deploy.py --install 只适用于全新安装，会拒绝覆盖。不要用重新初始化账号或导入旧 realm 的方式升级。

以下门户更新脚本只适用于已经完成固定挂载、root 登录及监控改造的当前平台，执行器兼容时仅替换门户，保留数据库、Keycloak、执行器及开发容器。它不是从原始 1.0/1.1 部署包到新平台的通用自动迁移器。老站点需逐项审核数据库、挂载和执行器兼容性。

# 先校验和导入新包镜像，不会重启现有容器
cd /mnt/juicefs/software/dev-resource-platform-release-2026.10.21
sha256sum -c SHA256SUMS
docker load -i images-linux-amd64.tar.gz

cd /mnt/juicefs/software/dev-resource-platform
# 备份名必须唯一；下例仅展示一次执行的命名方式
python3 scripts/history_backup.py history-before-release-20261021
python3 scripts/backup.py --verify-restore
# 当前站点已是本版，无需重复执行下面的更新命令。
# 需要更新门户且完成兼容审查时：
python3 scripts/upgrade_history.py \
  --backup .remote-dev/backups/history-before-release-20261021 \

脚本保留旧门户容器，验证健康接口、账户/凭据哈希、私钥哈希及其他运行容器身份。失败时自动恢复旧门户。它不自动同步宿主机代码；需要更新源文件时先备份 app/ 并从校验过的 source 包中仅更新 app/，不要覆盖 runtime/、data/、.remote-dev/ 或既有账号文件。实际服务读取的是构建进镜像的 /opt/platform/app。

成功后的人工回滚：先通过 docker ps -a --filter name=drp-portal 找到脚本保留的旧门户名称，停止并移走新门户，再将旧门户改回 drp-portal 并启动。不要同时启动两个门户控制器。这个回滚不回退业务数据库；本版数据库变更采用增量建表/加字段。需要数据库回退时按灾难恢复流程并使用一致的旧代码和备份。

10. 恢复流程

先确定故障范围。仅门户故障可保留所有数据并恢复门户。整机或数据库故障需同时准备：本部署包、同一时点数据库 dump、服务 secrets、data/.cluster-id、用户文件和各节点连接配置。

  1. 在维护窗口停止门户/执行器/Keycloak，避免恢复过程中继续写库；不要停止仍需保留的独立开发容器。
  2. 恢复相同的存储挂载与目录，校验 data/.cluster-id 和配置中的 storage_id 相同；恢复 secrets 权限及正确 host_ip/public_url。保持原端口、OIDC client secret 与数据库密码一致。
  3. 从部署包加载镜像，用原数据库卷启动原数据库服务；若数据库损坏，用受控备份恢复。数据库整体恢复会覆盖恢复点之后的账号和业务记录，应先留存故障现场。
  4. 先启动 Keycloak，再启动执行器；检查其 inventory 和 storage/check，确认节点 Docker 身份与数据库登记一致。最后启动门户。换了 Docker 主机时 engine ID 会改变，需人工审核节点身份，不能跳过校验。
  5. 先核对各环境到期时间、runtime_id、GPU 分配和实际容器再恢复自动控制。数据库旧快照中的过期环境在控制器恢复后可能被正常回收。
  6. 分别验证管理员与开发者登录、密钥登录、三盘读写、监控、历史查询及导出。
# 在临时数据库中练习恢复，不覆盖在线 platform：
docker exec drp-database createdb -U platform drp_restore_check
cat /受控备份/platform.dump | docker exec -i drp-database \
  pg_restore -U platform -d drp_restore_check --exit-on-error
# 核对关键表后，只删除此次创建的临时数据库：
docker exec drp-database dropdb -U platform drp_restore_check

恢复到新的默认安装位置时不要先运行初始化脚本再覆盖数据库。先恢复原服务密钥和数据，再以原有容器配置/审核后的 bootstrap services 命令启动。保留原主机配置记录可以避免重新分配地址、端口和挂载。bootstrap.py --phase services --keep-identity 仍会替换门户和执行器，应在维护窗口使用，不作为本次发布操作。

11. 增加计算节点与重新构建

新节点需挂载同一 JuiceFS 项目目录、相同 .cluster-id，配置本机固定数据父目录，并准备驱动、Docker 与 NVIDIA Toolkit。节点代理使用单独令牌与 HTTPS 证书；不会把控制节点 SSH 密码写进平台。

# 以下命令在新计算节点本机执行；示例 node-id/IP 应替换为真实值
cd /mnt/juicefs/software/dev-resource-platform
python3 scripts/deploy_node.py --node-id server004 --host 172.16.9.21 \
  --image dev-resources/platform:2026.10.21 \
  --bundle /mnt/juicefs/software/dev-resource-platform-release-2026.10.21/images-linux-amd64.tar.gz
# 然后管理员在“节点资源”登记该可信连接，核对 Docker 身份、共享存储和接单开关。

导入镜像后还需让新节点具有目录中登记的开发镜像；此离线包包含该镜像。其他自定义镜像应在目标节点预先导入并确保相同标签对应相同镜像 ID。默认固定私有目录不会跨节点搬迁。

12. 常见问题与发布清理

现象排查重点
登录失败 / 无法修改密码检查门户 /auth 代理、Keycloak 就绪与 issuer；检查实际用户密码和 account 客户端 manage-account/view-profile 角色。不要用陈旧的 initial-access.txt 推断当前密码
申请环境提示挂载未就绪检查 JuiceFS、.cluster-id、机器 IP 映射和 /data-local 实际挂载来源；空目录/掉挂会被拒绝。检查执行器的父目录与 /share 读写 bind
GPU 显示 0 张检查宿主机 nvidia-smi、Docker NVIDIA runtime、执行器 DeviceRequests；--no-gpus 演练实例本来不暴露 GPU
共享卡显存不足 / 独占任务等待分配/访问权限不代表空闲算力；外部训练容器也可能占卡。先查进程，不自动杀其他任务
开发者看不到 GPU 进程需要本人处于 running 的开发环境实际分配到该卡；未分配卡不会显示其他卡进程。管理员可看全量
历史面板暂时无数据等待 60 秒采样；检查节点在线、采集线程与选择的用户/项目/时间范围；指标超过 30 天会清理
SSH 密码登录失败本版使用 root 公钥认证，密码登录关闭。确认申请时公钥与客户端私钥匹配，端口以环境详情为准
停止后文件仍占空间固定目录会持久保留；自行清理 /data、/root 的无用输出/环境。超过 700GB 及时清理，勿删除其他用户数据
包校验失败 / INCOMPLETE不要部署该包。对照 SHA256SUMS 重新复制；INCOMPLETE 表示打包失败，需重发
